# 第 5 章：消息路由

> 目标：理解多个 Agent 之间如何通信，防环路机制，以及同步/异步两种路由的取舍。

## 5.1 这一章解决什么问题

单个 Agent 能思考和用工具了。但很多任务需要**多个 Agent 分工合作**——研究员搜索资料、作家写报告、审核员把关。它们之间要互相传递消息。

这就需要一个**消息路由**机制：A 发消息给 B，B 处理后发给 C。本章讲清楚这套机制，包括它曾经的两个隐患（递归栈溢出、互发死循环）以及现在的双层防护。

## 5.2 Message——消息协议（`core/message.py`）

Agent 间通信的基本单元：

```python
class Message:
    def __init__(self, sender, receiver, content, msg_type="text",
                 metadata=None, max_hops=128):
        self.id = uuid4()          # 唯一标识
        self.sender = sender       # 发送者 agent_id
        self.receiver = receiver   # 接收者 agent_id
        self.content = content     # 内容（文本/字典/任意）
        self.type = msg_type       # 类型（text/action/result 等）
        self.timestamp = now()     # 时间戳
        self.metadata = metadata   # 扩展字段
        self.hops = ...            # 当前转发链深度（自动继承）
        self.max_hops = max_hops   # 跳数上限（防互发死循环）
```

`content` 可以是任意类型——字符串、字典、甚至嵌套结构，由 Agent 自己约定怎么解析。

**hops 的继承机制**：Agent 在处理消息期间调用 `send()` 创建的新消息，会通过 ContextVar 自动继承当前链路深度 +1。路由器在投递前检查 `hops >= max_hops`，超限即丢弃——两个 Agent 互相回复形成死循环时，链路在第 128 跳被截断，并计入 `stats["hop_limit_drops"]`。

## 5.3 Router——同步消息总线（`core/router.py`）

Router 是中心化的消息总线，所有 Agent 注册到它上面：

```python
from core import Router, Message

router = Router()
router.register_agent(researcher)   # 自动绑定 researcher.router = router
router.register_agent(writer)

# researcher 给 writer 发消息
router.route_message(Message(
    sender="researcher",
    receiver="writer",
    content="这是研究资料：...",
    msg_type="research_result"
))
```

`route_message` 的内部逻辑：
```
1. 查 routing_rules（可覆盖 receiver）
2. 记入 message_history
3. 找到 receiver 对应的 Agent，调用 agent.receive(message)
```

### Agent 怎么发消息

Agent 通过 `send()` 方法发消息，它自动走 Router：

```python
# 在 Agent 的 receive() 里
def receive(self, message):
    result = self.think(message.content)
    self.send("writer", result, "research_result")   # 发给 writer
```

`send` 内部：构建 Message → 调用 `self.router.route_message(message)`。

### 异常边界

Router 的 `route_message` 用 try/except 包裹 `agent.receive()`：

```python
try:
    self.agents[receiver_id].receive(message)
except Exception as e:
    logger.exception("Agent 处理消息异常")  # 记录但不中断
    self.stats["routing_errors"] += 1
```

**一个 Agent 崩溃不会中断整个消息流**——这是工程健壮性的关键。

## 5.4 同步路由的递归陷阱（已修复，但值得理解）

早期版本的同步 Router 有个隐蔽的问题。看这个链路：

```
router.route_message(msg)            # ① 路由到 researcher
  └─ researcher.receive(msg)         # ② researcher 处理
       └─ researcher.send("writer", ...)   # ③ 内部又调 route_message
            └─ router.route_message(msg2)  # ④ 路由到 writer（同一调用栈！）
                 └─ writer.receive(msg2)   # ⑤ writer 处理
                      └─ writer.send("user", ...)  # ⑥ 又调 route_message
                           └─ ...          # ⑦ 继续嵌套
```

**每一跳都叠在同一个调用栈上**——链路很长或出现循环（A→B→A→B...）就会 **RecursionError（栈溢出）**。这是同步"直接调用"模型的固有缺陷：`route_message` 不是把消息"投递"出去，而是"立即处理"。

**现在的解法是迭代泵**。`route_message` 不再直接调用 `agent.receive()`，而是把消息放进待投递队列，由一个循环逐条处理：

```
route_message(msg)
  └─ pending.append(msg)        # 只入队
  └─ pump 循环（栈深恒定）：
       ├─ 取出 msg → agent.receive(msg)
       │    └─ receive 里再 send？→ 新消息进 pending，立即返回（不递归！）
       └─ 继续处理下一条……
```

Agent 在 `receive` 期间转发的消息进入队列等外层循环处理，**调用栈深度恒定**——任意长的转发链都不会溢出。配合 5.2 节的 hops 上限，无限循环也会被截断。

## 5.5 AsyncRouter——异步路由（`core/async_router.py`）

迭代泵解决了栈溢出，但同步 Router 仍是**串行**的——一条消息处理完才能处理下一条。AsyncRouter 用 **asyncio.Queue** 把"投递"和"处理"解耦，面向**并发**场景：

```
AsyncRouter.route(msg)
  └─ await queue.put(msg)     # 只入队，立即返回（不调用 receive）
                                消息处理在后台协程里进行
```

### 工作原理

```
         ┌──────────────────────────┐
route ──►│      asyncio.Queue       │
         │  [msg1] [msg2] [msg3]... │
         └────────────┬────────────┘
                      │ 逐个出队
                      ▼
              ┌──────────────┐
              │ 消费协程      │ ──► agent.receive_async(msg)  # 或 executor 里的同步 receive
              │ (后台运行)    │
              └──────────────┘
```

Agent 的 `send` 把消息**入队就返回**，即使 A→B→A→B 互相转发，每跳都是"入队 → 出队"的循环，调用栈深度恒定。`max_concurrent` 参数可启动多个消费协程并发处理不同消息。

### 用法

```python
import asyncio
from core import AsyncRouter, Message

async def main():
    router = AsyncRouter()
    router.register_agent(agent_a)
    router.register_agent(agent_b)
    await router.start()                          # 启动后台消费协程
    await router.route(Message("user", "a", "ping"))
    await router.drain()                          # 等待所有消息处理完
    await router.stop()

asyncio.run(main())
```

`stop()` 是优雅关闭：等待在途消息入队 → 投递哨兵 → 消费者排空本轮队列后退出；若期间又产生了链式消息会再清一轮，**不死等也不丢消息**。`drain()` 会把同步桥在途的消息计入等待，消息链不会中途"看起来空闲"就提前返回。

### 同步兼容桥

现有 Agent 的 `send()` 是同步的、会调 `router.route_message`。AsyncRouter 提供了 `route_message` 同步桥接方法：它把消息线程安全地调度入队就返回，让同步 Agent 无需改造也能享受异步的好处（接收者不存在时返回 `False`，与同步 Router 语义一致；`broadcast` 同样返回逐目标的 `{agent_id: bool}`）。

## 5.6 何时用 Router vs AsyncRouter

| 场景 | 推荐 |
|------|------|
| 简单流水线（A→B→C，深度浅） | Router（同步，简单直观） |
| 需要高并发处理消息 | AsyncRouter（队列天然异步，消费协程可并行） |
| asyncio 应用内集成 | AsyncRouter（与事件循环同呼吸） |
| 学习、原型、demo | Router（直观易懂） |

两者现在都防栈溢出（迭代泵 / 队列解耦）、都防环路（hops 上限），选型看并发需求而不是安全性。

## 5.7 一个完整的多 Agent 协作示例

```python
from core import Router, Message, Agent

class Researcher(Agent):
    def receive(self, msg):
        result = self.think(msg.content)        # 思考
        self.send("writer", result)             # 发给作家

class Writer(Agent):
    def receive(self, msg):
        report = self.think(f"整理成报告：{msg.content}")
        self.send("user", report)               # 发给用户

class User(Agent):
    def receive(self, msg):
        print("最终结果:", msg.content)

router = Router()
router.register_agent(Researcher("researcher", "研究员", llm_client=llm))
router.register_agent(Writer("writer", "作家", llm_client=llm))
router.register_agent(User("user", "用户"))

router.route_message(Message("user", "researcher", "研究量子计算"))
# 流程：user→researcher→(思考)→writer→(思考)→user→(打印)
```

## 5.8 Router vs Team：两种协作模型怎么选

PyAgentKit 有**两套并行的多 Agent 协作机制**，它们不叠加使用，按场景二选一：

| 维度 | Router（本章） | Team（下一章） |
|------|---------------|----------------|
| **通信方式** | Agent 互发消息（send/receive） | Process 通过 SharedContext 传递产出 |
| **流程控制** | 分散（每个 Agent 决定转发给谁） | 集中（Process 决定执行顺序） |
| **共享状态** | 各自独立 memory | SharedContext 共享黑板 |
| **适合** | 动态对等通信、按需路由 | 有分工、有共同目标的流水线 |
| **可观测** | Router 消息历史 + 统计 | Trace 执行追踪 |

**简单记法**：
- Agent 之间需要**对话/协商/转接** → 用 Router
- Agent 之间需要**分工/流水线/团队目标** → 用 Team

> 详细的架构决策与理由见 [ADR-0001](adr/0001-team-vs-router.md)。
